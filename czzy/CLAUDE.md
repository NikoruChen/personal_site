# CLAUDE.md — `czzy/`

The RSS feed for the podcast 《粗枝壮叶》. See the repo-root `CLAUDE.md` for what lives
here and the rules for editing `feed.xml`.

## `feed.xsl` — what a person sees at the feed URL

`feed.xml` is a public URL, so `feed.xsl` renders it as a real page of the site: the show's
artwork, title, host, description and subscribe address, then every episode with its date,
duration, player and show notes. It's wired up by the
`<?xml-stylesheet type="text/xsl" href="feed.xsl"?>` line on line 2 of `feed.xml`; browsers
apply it, podcast apps ignore it. **Keep that line** — losing it drops visitors onto raw XML.

Treat it as a page of the site, not a debug view: **no internal or technical chrome**
(guids, byte counts, enclosure URLs, "generated by…" notes, Apple's English category
names). Its colors, type scale and header/footer are copied from `index.html` — when that
design changes, change this to match.

Anything that is for readers only — platform links, a subscribe box, a banner — belongs
**in `feed.xsl`, never in `feed.xml`**. The stylesheet is a separate file that only browsers
fetch, so page content can be added freely without touching what podcast apps parse. The
收听平台 buttons work this way: a block of `<xsl:variable>`s at the top of `feed.xsl` holds one
URL per platform, and a button renders only for the ones that have a URL. That block is the
only part of the file meant to be edited routinely.

To look at it: `python3 -m http.server` from the repo root, then open
`http://localhost:8000/czzy/feed.xml`. A `file://` path won't work — browsers refuse to
load a stylesheet for a local file. `feed.xsl` is presentation only; nothing in it can
change what a podcast app sees.

## Read this before every edit

Apple's spec is the standard this feed is held to — a feed that violates it gets rejected
or silently mis-rendered in Apple Podcasts, and the other apps follow Apple's lead:

**https://podcasters.apple.com/support/823-podcast-requirements**

Fetch that page and read it **every time** you are about to change anything in this
directory — `feed.xml`, `cover.png`, or any file added later. Don't work from memory of
what the requirements say; they change, and the details (tag names, required vs.
recommended, artwork dimensions, category names) are exactly what breaks a feed.
