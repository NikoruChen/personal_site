# CLAUDE.md — `czzy/`

The RSS feed for the podcast 《粗枝壮叶》:

- **`feed.xml`** — served at `https://damu.blog/czzy/feed.xml`. **The podcast's source of
  truth**: there is no manifest anywhere, so this one file holds both the show metadata (the
  `<channel>` block) and every published episode (`<item>`).
- **`cover.png`** — the show artwork. In this repo only because the feed cites it by public URL.
- **`feed.xsl`** — a redirect; see below.

The tooling that maintains `feed.xml` lives in the separate, private **`guild`** repo
(`podcast/podcast-publish/`), where the `podcast-publish` skill uploads each episode's audio to Cloudflare R2
(behind `czzy.damu.blog`) and splices a new `<item>` into this file.

How and why all of that works is documented there. What lives here is the guardrails — what must
not be done to these files, and what each rule protects. Keep it that way: a note added here says
what to avoid and points at `guild`, it does not re-explain the pipeline.

## Read this before every edit

Apple's spec is the standard this feed is held to — a feed that violates it gets rejected
or silently mis-rendered in Apple Podcasts, and the other apps follow Apple's lead:

**https://podcasters.apple.com/support/823-podcast-requirements**

Fetch that page and read it **every time** you are about to change anything in this
directory — `feed.xml`, `cover.png`, or any file added later. Don't work from memory of
what the requirements say; they change, and the details (tag names, required vs.
recommended, artwork dimensions, category names) are exactly what breaks a feed.

## Editing `feed.xml` by hand — four rules

- **An episode may already be waiting to go out.** A prepared release sits on a `publish/*`
  branch until its `<pubDate>` arrives, and reaches `main` by fast-forward — so an edit landing
  here first strands it, and the release passes with nothing appearing. Check before you touch
  the file, and leave it alone while a branch is pending:
  ```bash
  git ls-remote --heads origin 'publish/*'
  ```
  What does the merging, and what it refuses, is `.github/workflows/publish.yml`.
- The **`<channel>` block is fair game** — that's how the show's title, description, categories
  and owner email change. Run `feed.py validate` in `guild` afterwards; Apple rejects category
  names that don't match its list exactly.
- **Never touch an existing `<item>`'s `<guid>`.** It's how podcast apps recognize an episode
  they already have; change one and every subscriber re-downloads it as new. `feed.py validate`
  in `guild` hard-fails if a published guid disappears.
- **Everything below an episode's `<!-- czzy:footer -->` comment is generated** — the show blurb,
  where to listen, the host's handles, appended when the episode was added to the feed. Editing it
  here changes that one episode and puts it out of step with its source, which is
  `guild/podcast/podcast-publish/footer.md`; edit that instead. The footers legitimately differ between
  episodes — don't reconcile them.

## `feed.xsl` — what a person sees at the feed URL

`feed.xml` is a public URL, so a browser opening it must not land on raw XML. `feed.xsl` is
what prevents that, wired up by the `<?xml-stylesheet type="text/xsl" href="feed.xsl"?>` line
on line 2 of `feed.xml`; browsers apply it, podcast apps ignore it. **Keep that line.**

The stylesheet does one thing: send the browser to **`/#/podcast`**, which is where the podcast's
page lives. Being a screen of the site's SPA, that page shares the site's header, footer and
styles by being part of the same document.

**So the page is `js/screens/podcast.js` and `styles/podcast.css`, not this directory** — this
feed reaches it as plain objects from `js/content.js`, like every other screen's content.
Anything for readers only — platform links, a subscribe box, a banner — belongs there and
**never in `feed.xml`**, which holds only what podcast apps parse. The 收听平台 buttons work this
way: the `PLATFORMS` list in `js/screens/podcast.js` holds one URL per platform, and a button
renders only for the ones that have a URL. That list is the part meant to be edited routinely.

Keep the page free of internal or technical chrome — guids, byte counts, enclosure URLs,
"generated by…" notes, Apple's English category names. `itunes:author` is in the same family:
the host is obvious on their own site.

To look at it: `python3 -m http.server` from the repo root, then open
`http://localhost:8000/czzy/feed.xml` and watch it bounce. A `file://` path won't work —
browsers refuse to load a stylesheet for a local file. Nothing in `feed.xsl`, or in the page it
redirects to, can change what a podcast app sees.
